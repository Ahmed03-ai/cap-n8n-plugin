<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CAP service event -> n8n start | Authorized CAP writes produce external workflow side effects. |
| CAP transaction -> Phase 3 outbox | Annotation handler queues execution state before post-commit dispatch. |
| Runtime errors -> CAP request | n8n side-effect failures must not turn successful writes into failed writes by default. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Tampering | `AnnotationRegistrar.js` | mitigate | Register only `after` handlers on served CAP service entities for CREATE/UPDATE/DELETE after normal CAP authorization and validation have accepted the request. |
| T-04-02-02 | Denial of Service | `AnnotationRegistrar.js` | mitigate | Catch runtime side-effect failures, call Phase 3 `n8n.start(..., { _req: req })`, and rely on post-commit/outbox behavior so n8n failures do not roll back CAP writes by default. |
| T-04-02-03 | Information Disclosure | `AnnotationRegistrar.js` logs/results | mitigate | Use `cds.log('n8n')` metadata-only logging and preserve Phase 3 sanitized public execution DTOs. |
| T-04-02-04 | Elevation of Privilege | annotated `if` conditions | mitigate | Consume Plan 04-01 `compileCondition` and `evaluateCondition`; never evaluate JavaScript strings. |
| T-04-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install task exists in this plan; if an executor adds one, stop and run Package Legitimacy Gate before installing. |
</threat_model>
