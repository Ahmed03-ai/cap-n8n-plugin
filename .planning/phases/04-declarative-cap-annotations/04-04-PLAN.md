<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Demo CDS annotations -> package registrar | Demo service projection annotations activate package-owned runtime handlers. |
| Demo JavaScript service -> annotation runtime | Removing hard-coded handler prevents duplicate side effects and demo-owned behavior. |
| Annotation propagation -> served services | CAP annotation propagation can fan out across projections if annotations are placed on the wrong layer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Tampering | `demo-app/srv/admin-service.cds` | mitigate | Place n8n annotations on `AdminService.Books` service projection and verify compiled keys there to avoid unintended domain-wide fan-out. |
| T-04-04-02 | Denial of Service | `demo-app/srv/admin-service.js` | mitigate | Remove hard-coded n8n handler so side effects route through package-owned non-blocking annotation runtime and Phase 3 outbox. |
| T-04-04-03 | Information Disclosure | demo test fixtures/results | mitigate | Use local test values only; do not commit API keys, private keys, production credentials, or raw payload assertions in public DTOs. |
| T-04-04-04 | Elevation of Privilege | demo annotation condition | mitigate | Use the same safe `if: 'stock > 0'` condition path covered by Plan 04-01 source gates. |
