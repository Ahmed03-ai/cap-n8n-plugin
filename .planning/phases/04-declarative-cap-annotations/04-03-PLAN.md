<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CAP service event -> execution query | Annotated write events select active execution records to cancel. |
| Execution query -> cancel side effect | Matching records transition through Phase 3 cancellation semantics. |
| No-match/failure -> CAP request | Cancellation absence or failure must not block the CAP data mutation by default. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | `CancellationResolver.js` | mitigate | Require workflowId plus businessKey and/or tag; use allowlisted `queryExecutions` filters instead of direct table updates. |
| T-04-03-02 | Denial of Service | cancel handlers | mitigate | Catch resolver and cancel failures; log metadata-only errors; do not throw from annotation cancellation handlers by default. |
| T-04-03-03 | Information Disclosure | cancel logs/results | mitigate | Reuse Phase 3 sanitized `cancel` and query DTOs; do not log payloads, inputs, headers, requestBody, stack, or secrets. |
| T-04-03-04 | Repudiation | no-match cancellation | mitigate | Log a non-blocking warning with workflowId, entity, event, businessKey, and tag when no active match is found. |
| T-04-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install task exists in this plan; if an executor adds one, stop and run Package Legitimacy Gate before installing. |
</threat_model>
