<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CAP transaction -> external n8n webhook | Workflow dispatch must not leave CAP before the local execution intent and internal outbox payload are committed. |
| internal dispatch outbox -> public execution DTOs | Internal retry payloads must stay private and never leak through query/cancel results. |
| retry loop -> n8n workflow runtime | Retried dispatch can create duplicate external side effects if correlation is not stored. |
| external n8n response/error -> persisted execution | External data is persisted for developer inspection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | dispatch timing | mitigate | Create the queued record and internal outbox payload first, dispatch from `req.on('succeeded')` or `dispatchPending`, and test rollback no-dispatch plus commit after-dispatch behavior. |
| T-03-05 | Repudiation | retry attempts | mitigate | Persist attempts and correlation metadata on every dispatch attempt so duplicate or ambiguous starts can be detected later. |
| T-03-06 | Information Disclosure | persisted dispatch errors | mitigate | Store sanitized errors only and exclude headers, auth values, input payloads, request bodies, stacks, and configured secret strings. |
| T-03-06B | Information Disclosure | internal dispatch payload | mitigate | Keep payloads in an internal outbox only and assert query/getExecution DTOs never return the payload. |
| T-03-07 | Denial of Service | dispatch retries | mitigate | Reuse Phase 2 bounded retry/timeout settings rather than unbounded worker retries. |
</threat_model>
