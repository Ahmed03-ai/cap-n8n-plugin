<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CAP caller -> query filters | Caller-provided filters and paging bounds shape database queries. |
| execution store -> CAP-visible DTOs | Stored execution metadata is returned to application code. |
| duplicate policy -> workflow side effects | Duplicate policy can allow, reject, or reuse starts with external workflow consequences. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-08 | Tampering | query filters | mitigate | Validate allowed filter keys, status values, limit, and offset before building CAP queries. |
| T-03-09 | Information Disclosure | query results | mitigate | Return sanitized DTOs only and exclude raw inputs, payloads, headers, auth values, request bodies, and stack traces. |
| T-03-10 | Repudiation | duplicate starts | mitigate | Persist correlation metadata and include duplicate policy, active execution IDs, and ambiguous flags in safe result envelopes. |
| T-03-11 | Denial of Service | large execution lists | mitigate | Enforce bounded pagination and avoid all-row in-memory slicing for CAPAPI-06. |
</threat_model>
