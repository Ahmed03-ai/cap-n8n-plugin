<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n editor parameters to CAP OData requests | Operation, service path, entity set, key parts, key predicate, and Body become outbound HTTP method, URL, headers, and JSON body. |
| CAP HTTP response to n8n items | CAP success and failure payloads become node output or node-visible errors. |
| Delete operation selection to destructive CAP request | User-selected Delete plus key becomes a destructive `DELETE` request. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Information Disclosure | `SapCap.execute`, `ODataResponse.ts`, tests | mitigate | Route every CRUD failure through sanitized helpers and assert no credentials, tokens, auth headers, request bodies, raw response bodies, or stack traces appear in thrown errors or continueOnFail items. |
| T-07-02-02 | Tampering | CRUD URL construction | mitigate | Reuse normalized service path, entity-set, manual predicate, and Plan 07-01 metadata key helpers; reject URL boundary characters and missing composite-key parts before HTTP. |
| T-07-02-03 | Information Disclosure | JSON Body validation | mitigate | Parse Body locally but return allowlisted validation copy only; never include raw Body JSON in errors, logs, docs, or source gates. |
| T-07-02-04 | Tampering | Delete request builder | mitigate | Require explicit key input, add no confirmation checkbox per D-10, send DELETE with no body per D-12, and test no-body behavior plus not-found handling. |
| T-07-02-05 | Denial of Service | malformed successful mutation responses | mitigate | Treat invalid JSON or unexpected response shape as sanitized `responseShape` errors instead of retry loops or raw output. |
| T-07-02-SC | Tampering | npm installs | mitigate | No package installs are planned; package changes require a blocking legitimacy review. |
</threat_model>
