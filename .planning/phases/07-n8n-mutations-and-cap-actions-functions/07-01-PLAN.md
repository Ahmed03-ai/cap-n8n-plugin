<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n parameters to key helpers | User-supplied entity names, manual key predicates, and key part values become OData URL path segments. |
| CAP metadata to node descriptors | Remote `$metadata` XML controls key descriptors shown or used by the node. |
| helper errors to n8n UI/tests | Validation and metadata failures become node-visible errors or continue-on-fail items. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01-01 | Information Disclosure | `ODataMetadata.ts` and metadata tests | mitigate | Preserve sanitized `responseShape`/metadata errors and assert no credentials, tokens, auth headers, stack traces, request bodies, or metadata response bodies serialize into errors. |
| T-07-01-02 | Tampering | `buildKeyPredicateFromParts` and `normalizeKeyPredicate` | mitigate | Reject URL boundary characters, require all composite-key parts per D-06, and use type-aware literal formatting per D-07. |
| T-07-01-03 | Information Disclosure | key validation errors | mitigate | Return allowlisted validation messages and do not include raw key object values or request-body content. |
| T-07-01-04 | Tampering | destructive Delete behavior | transfer | Plan 07-02 consumes these helpers and must require an explicit key, send DELETE without a body per D-12, and return confirmation per D-09. |
| T-07-01-SC | Tampering | npm installs | mitigate | No package installs are planned; if an executor concludes a package is required, stop for package legitimacy review before modifying manifests or lockfiles. |
</threat_model>
